# FX11 Ultra v68 连接、空调与原版仪表接收测试版

日期：2026-10-31。LIVI 参考：`f-io/LIVI` commit `e7b20b818f052958afc95dcf91acc25c70643c02`。
这是代码与协议对齐后的测试包，尚未在测试 iPhone/FX11 上验收空调入口及完整原版仪表。

## 改动

- 同一 client type 的 RCS SETUP 重建旧通道，normal/high priority CAF 各自独立。每次使用新 streamID，旧 TEARDOWN 不误关新通道。EOF、关闭和初始化失败释放监听器及车辆订阅。
- USB、无线的 identification 和 StartSession 使用同一主题资产标识、版本和 SDK。普通仪表模式不增加主题启动字段。
- 主题模式增加 UI Sync 的 RequestLayout 初始化，匹配主题主屏/仪表屏名称、实际视频 UUID 和 display plugin。仅开启空调时保留普通视频配置，并补充 LIVI 的 instrument plugin 面板声明。
- 空调 CAF 由单个电源字段扩展为总开关、A/C、左右目标温度、风量、内循环、AUTO，以及风机开启/自动的只读反馈和座位资源描述。数据通过 FX11 Demo 的 ECARX 接口获取；单位、范围和当前可用性校验不通过时保留未知。拒绝未实现、无效或已断开会话的写入；同一事务不重复下发。
- 高级 → 博越 L 仪表显示 → 本地仪表样式增加「CarPlay Ultra 原版仪表（实验性）」。显示手机的完整副屏视频，不加本地仪表圆盘，不复用普通地图的裁剪、缩放或镜像主屏设置。收到协商后的新视频帧才允许接管仪表屏。
- 原有样式枚举序号不变；保留普通 CarPlay、现有自定义仪表、原厂叠加、方控、ESP32 传输及 HUD 功能。无需更新 ESP32 固件。
- 原版仪表选择和空调开关独立：关闭空调时仅发布资源描述，不连接或写入车辆空调接口。

## 原版仪表的验证边界

采用 Apple CarDDPAssets 实际元数据 `44C9FA31ECCN:985` / SDK `19.0`，主题屏名 `Center_Display`、`Cluster_Display`，DigiRing 布局。APK 不包含 Apple CoreAnimation 或美术资源包，不模拟已完成本地主题渲染。

这次完成的是主题启动、布局协商与手机视频接收链路，**不能据此保证 iPhone 会把原版所有圆盘和车辆数据绘制到副屏视频中**。主题若要求车端 Local UI 合成，本版还不具备该能力。原生圆盘所需完整 CAF 车况绑定也未补全；不能把现有本地 FX11 仪表的数据正确显示当作原生 Ultra 已验收。

空调总开关曾在 FX11 Demo 验证；扩展温度等字段经过代码/模拟后端测试，仍需本 APK 实车回读和操作验收。选择了 Ultra、主题协商成功、视频出帧、空调入口出现是四个不同阶段。

## 测试步骤

1. 覆盖安装同签名 v68，不卸载、不清数据。先保留当前仪表样式，确认普通 CarPlay、音乐、地图、ESP32 正常。
2. 开启「CarPlay 空调开关（实验性）」后使用「立即重连」，查看桌面各页和底部栏是否出现入口。
3. 选择「CarPlay Ultra 原版仪表（实验性）」，点击「立即重连」，在 iPhone 保持 CarPlay Ultra 选项。可用现有 MODE 或设置页的切换原厂/自定义仪表按钮切换输出。
4. 若仍无画面，记录是等待提示、只有地图、完整原版圆盘还是黑屏，导出诊断。不要把仅地图或等待界面判为完整 Ultra 成功。
5. 停车时再验证空调界面状态和操作；对照原厂状态。无入口时无需盲目反复切开关。
6. 可随时选择原有经典等仪表样式并重新连接，恢复旧显示路径；关闭空调开关再重连可停止额外车控声明。

诊断包括同类通道 replaced/removed、协商启用字段、主题和布局标识、UI Sync ready、CAF 收发类型及真实回读。日志不输出认证私钥、证书内容或 Wi-Fi 密码。
